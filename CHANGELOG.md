# Changelog

All notable changes per release. Each release on GitHub carries its verification results
(`docs/release-notes/<tag>.md`) and SHA-256 checksums for every file.

## [0.4.0] — 2026-11-27

Text formats open in the preview, and files the user hands over (a folder, files, a drop) lift the "only the
opened file" and 50 MB limits. Checked in real Orca 1.4.277: `docs/evidence/v0.4.0/`, `docs/evidence/text-editors/`.

### Fixed
- **URDF, xacro, KiCad, draw.io, ASCII DXF, STEP/IGES/BREP, OBJ and other text formats showed only source.**
  Orca offers a `contentKind: "bytes"` editor only for binary files: a NUL byte in the first 8 KB, or an image/PDF
  suffix. Every editor of this plugin was `bytes`. The manifest now has 6 bytes editors and 10 text editors (16
  max), generated by `tools/gen-text-editors.mjs`. A text document carries no suffix, so `textType()` picks it from
  the content. Text files now open in the preview by default; Orca's own types (`.txt .csv .tsv .html .htm`) open
  in Source, with the preview in the view toggle. RTF/HTML `.doc` and XML `.xls` preview too. The harness routes
  fixtures the way Orca does (`tools/harness/route.mjs`), so this cannot hide again.

### Added
- **Companion files for 3D, robot and DXF previews.** The editor only gets the opened file, but the sandboxed frame can
  read files the user picks (📁 toolbar button: a folder, Shift: single files) or drops. References resolve by the longest
  path tail and relative to the referring file (`core/refs.ts` on top of `core/companions.ts`):
  - Robot Preview: meshes (STL binary/ASCII, COLLADA with textures, OBJ with `.mtl` and textures, glTF/GLB) replace
    their placeholders live; the joint pose stays. `scale`, origins and materials as in rviz (a mesh's own colours,
    else the URDF material; COLLADA up-axis not turned, unit scale kept). `xacro:include` (`$(find pkg)/…`, relative,
    nested; cycles stopped) is read and the file expanded again; the "not loaded" lists shrink and keep a hint to
    pick the package or workspace folder.
  - 3D Preview: OBJ `mtllib` and textures, glTF external `.bin` and images, DAE/FBX/3MF textures, all through blob:
    URLs (images and buffers only). A glTF without its `.bin` is a friendly refusal with the 📁 button.
  - CAD Drawing Preview: DXF external references (xref blocks; nested xrefs, cycles reported) are parsed and
    inserted with their layers as `XREF|layer`; IMAGE entities draw the picked raster. Missing ones are listed above
    the drawing.
- **File Preview panel** (right sidebar, `panel/main.ts`): "Open file…", "Open folder…" and drag and drop show any
  supported file with the same renderers, without Orca's 50 MB editor limit (renderers' own limits, up to 1 GB) and for
  files outside a workspace; files opened together are companions. Same `sandboxed-ui` execution, no capabilities; a
  panel does not use one of the 16 editor slots.
- `tools/make-companion-samples.mjs` (samples/companions: a ROS-style package, OBJ+MTL+texture, glTF+bin, DAE+texture,
  DXF with xrefs and an image), `tools/harness/companions.mjs` (folder picker, synthetic drop, panel, 150 MB STL),
  `tools/vendor-one.mjs`; three.js bundle adds `MTLLoader` and `TextureLoader` (+4 KB). Evidence:
  `docs/evidence/companions/`.
- **Companion files for KiCad, SolidWorks and EPLAN** (📁 / drop, same `core/companions.ts`). Evidence:
  `docs/evidence/companions-eng/`.
  - KiCad: with the project folder, a root schematic lists its sheet tree (pages, nested sheets, missing or recursive
    sheets in a note with a hint) and opens sub-sheets (select, double-click, ↑) with their instance references and
    units (KiCad 7+ symbol `instances`, KiCad 6 `symbol_instances`); `.kicad_pro` opens the root schematic and board;
    the project's custom drawing sheet (`.kicad_wks`: lines, rects, texts, polygons, repeats, page-1 options, text
    variables) is drawn for schematics and boards; a `.kicad_wks` opened on its own shows as a template. Matches `kicad-cli` 10.0.5 on the generated sample project.
  - SolidWorks: **3D assembly** tab. Component placements come from `COMPINSTANCETREE` (column-major 4×4 per instance,
    nested sub-assemblies, suppressed/hidden, display states; verified on 5 public assemblies against their stored
    bounding boxes); meshes from the assembly's own `FaceTessellations` (2015+, no parts needed) or from given part files
    (2014 OLE files), recursing into given sub-assemblies; placement table in References. Drawings: referenced
    models open when given.
  - EPLAN: macros (`.ema`, `.emp`, and **Draw** for macros in `.edz`) drawn from PXF (lines, arcs, curves, texts,
    rectangles, device black boxes; per variant). Link files read the project folder (`.edb`): ProjectInfo.xml, page
    descriptions and a **Parts** tab from `Article.eod` (also in `.zw1` backups). The `.edb` store is EPLAN's own
    `.eod`/`.eox` format (not SQLite/SQL CE/XML); schematic pages stay undrawn.
  - New text editor family `eplan` (`.ema` `.emp`): 16 editors in total. Samples: `tools/make-kicad-project.mjs`,
    `tools/make-sw-assembly.py`, `tools/make-eplan-project.py`; harness `tools/harness/companions-eng.mjs`.
- 3D Preview: a model with a missing external texture drew black. The stand-in 1×1 PNG was corrupt; it is now a
  valid white pixel, and the view draws again once side textures have loaded.

## [0.3.0] — 2026-11-26

New viewers for CAD drawings, diagrams, electronics, robot descriptions (URDF/xacro) and engineering files, plus an Ubuntu 26.04 column in the Orca
compatibility CI. Checked in real Orca 1.4.263: `docs/evidence/v0.3.0/`.

### Added
- **Robot Preview** (`.urdf`, `.xacro`, `.urdf.xacro`): ROS robot descriptions in 3D with three.js. Own XML reader and
  xacro processor following ROS 2 xacro 2.x (properties: lazy, block, `default`, `remove`, `scope`; args; macros with
  `:=`, `^`, `^|` defaults, `*`/`**` blocks, `insert_block`, recursion, `xacro:call`; `if`/`unless`; `element`/
  `attribute`; `$(arg)`, `$(find)` → `package://`, `$(optenv)`, `$(eval)`) with a safe Python-expression evaluator
  (no `eval`/`new Function`). Output matches the PyPI `xacro` 2.1.1 package exactly on every comparable sample and on
  the ROS `urdf_tutorial` files (`tools/urdf/xacro-compare.mjs`). URDF: box, cylinder, sphere, capsule, origins,
  named/inline materials, fixed/revolute/continuous/prismatic/floating/planar joints, limits, mimic chains. UI: link/
  joint tree, joint sliders (continuous ±π), reset pose, visual/collision/frames/joint-axes toggles, click-to-select in
  3D, info bar (name, links, joints, DOF, extents). Meshes and `xacro:include` files cannot be read (the editor gets one
  file): meshes become labelled translucent placeholders and are listed, includes and their macros become notes; a
  macro-only xacro shows its macro list. Problems (missing links, two parents, loops, bad numbers) become notes.
  Evidence: `docs/evidence/urdf/`.
- three.js vendor bundle: geometry classes, `Raycaster`, `EdgesGeometry` added (+7 KB).
- **Orca compatibility CI on Ubuntu 26.04** (Docker; Orca 1.4.248, 1.4.253, 1.4.258 and 1.4.277), and Orca 1.4.277 on
  every OS. Local check: Ubuntu 26.04.1 LTS with Orca 1.4.277, 9/9 (`docs/evidence/platforms/ubuntu-26.04`).
- **File Preview DWG** — a separate plugin, published as [hangams84/orca-file-preview-dwg](https://github.com/hangams84/orca-file-preview-dwg) v0.1.0 (source in `dwg-plugin/`) (id `file-preview-dwg`, **GPL-3.0-or-later**, installs on
  its own; the main plugin stays MIT and unchanged) for AutoCAD `.dwg` drawings and `.dwt` templates. GNU LibreDWG
  (`@mlightcad/libredwg-web` 0.9.4, WebAssembly) reads the file in a module worker; the embind glue's two `new Function`
  sites are patched to closures (`tools/libredwg-patches.mjs`, verified under `node --disallow-code-generation-from-strings`).
  Canvas viewer: model space and paper-space layouts with viewports, layer toggles, blocks (rotated/scaled/mirrored/
  arrayed/nested), attributes, TEXT/MTEXT with Korean, dimensions, leaders, solid/pattern/gradient hatches with holes,
  polylines with bulges and widths, arcs, circles, ellipses, splines, line types, colours, line weights; pan/zoom/fit,
  dark/light background, info bar (version, units, extents). Unreadable or 3D-only files show the preview image stored
  in the DWG. R13–AutoCAD 2018 open (142 DWG files of LibreDWG's test data, R2.6–2018, all settle, 131 drawn, 7 show the stored preview image); evidence in `docs/evidence/dwg/`.
- `tools/harness/run.mjs --plugin dwg-plugin` (default unchanged), `tools/harness/dwg-interact.mjs`,
  `tools/check-dwg-plugin.mjs`, `tools/build-dwg-vendor.mjs`, `tools/make-dwg-samples.py`, `samples/dwg/`.
- **SolidWorks** (`.sldprt` `.sldasm` `.slddrw` `.slddrt` `.prtdot` `.asmdot` `.drwdot`): reads both containers (OLE
  compound files up to 2014 with `__ZLB` zlib frames, and the 2015+ disguised-ZIP container) without SolidWorks. Shows
  the saved preview pictures (PNG and bitmap), drawing sheet images, summary/custom/configuration properties, the
  release that saved the file and the save history, configurations, referenced files (assembly components, drawing
  models), component instances and feature names, and the stream list. **Parts** get a 3D view of the display mesh
  SolidWorks saved (three.js; triangles, not exact surfaces). Assemblies get no 3D view: their stored component meshes
  carry no placement. Files from 2001 and earlier (PKWARE implode) show pictures and properties only.
- **EPLAN Electric P8**: `.edz` part packages (7z or ZIP): parts list with search, part data (numbers, manufacturer,
  multilingual descriptions, dimensions, free technical properties), part pictures, PDF documents opened in the PDF
  viewer, macro names/types/variants. `.zw1` backups (and `.elp` `.elx` `.zx1` when they are archives): project
  properties from ProjectInfo.xml, backup info, page descriptions found in Page.eod, pictures, contents tree.
  `.elk` `.ell` `.elr` `.els` `.ela` link files: data directory and database version. Schematic pages and macro
  graphics are not drawn, and every page says so.
- Own **7z reader** with LZMA / LZMA2 decoders (written from the public-domain LZMA specification), Copy and Deflate
  coders; encrypted archives are reported as such.
- **Generic inspector** for registered files that cannot be read: format identification, size, entropy, hex dump and
  readable strings (and OLE stream lists) instead of a bare error.
- Samples generated by `tools/make-prop-samples.py`; harness walk `tools/harness/prop-interact.mjs`; evidence in
  `docs/evidence/prop/`.
- **Diagram Preview** for draw.io (`.drawio`, `.dio`) and Visio (`.vsdx`, `.vsdm`, `.vstx`, `.vssx`): a page picker
  (PageUp/PageDown), pan/zoom/fit, a dark canvas switch (◐, remembered) and links (page links switch pages, web links
  ask before opening; linked shapes carry a small badge). Text-looking `.drawio` files open in Orca's Source view first.
  - draw.io: `mxfile`/`mxGraphModel`, compressed pages (base64 + raw deflate + URI encoding, and older non-URI ones),
    layers, groups, swimlanes/containers, about 50 built-in shapes, edges (straight, orthogonal, elbow, entity-relation,
    curved, rounded, waypoints, fixed connection points, 20 arrow kinds, labels), fill/stroke/gradient/dashed/opacity/
    shadow/rotation/flip/fonts, HTML labels sanitised with DOMPurify, placeholders, embedded images. Unknown stencils
    draw as a dashed box with the stencil name. Written in-tree: the official viewer (Apache-2.0) is 3.6 MB, loads math,
    fonts and stencils from the network, injects `<style>` and evaluates code for some styles.
  - Visio: masters (geometry, text and cells inherited row by row, group masters), style sheets (line/fill/text
    chains), every Geometry row type (MoveTo, LineTo, ArcTo, EllipticalArcTo, NURBSTo, SplineStart/SplineKnot,
    PolylineTo, Ellipse, InfiniteLine, Rel* rows), groups, 1-D connectors with arrow heads, text blocks (character and
    paragraph rows, bullets, margins, alignment, rotation, fields, text background), fill patterns, legacy and
    multi-stop gradients, transparency, shadows, line patterns, theme colours and fonts, PNG/JPEG/EMF/WMF pictures,
    hyperlinks, page sizes and background pages; stencils (`.vssx`) show one master per page. Binary `.vsd` gets a
    clear message.
  - Fidelity on a generated corpus (`tools/make-diagram-samples.py`): draw.io against the official draw.io viewer,
    Visio against LibreOffice (Visio is not installed): `docs/evidence/diagram/`.
- **KiCad Preview** for `.kicad_sch`, `.kicad_pcb`, `.kicad_mod`, `.kicad_sym` and `.kicad_pro` (KiCad 6–10), drawn
  as SVG by an own S-expression reader with KiCad's stroke font (newstroke subset, CC0, via KiCanvas/MIT):
  - Schematic: library symbols with units and De Morgan body styles, pins with names/numbers and pin shapes, wires,
    buses and bus entries, junctions, no-connects, local/global/hierarchical labels and net class flags, power
    symbols, hierarchical sheets with pins (a toolbar list jumps to each sheet and names its file), text, text boxes
    (word-wrapped), graphics, fields, embedded PNG images, DNP marks, title block and paper size.
  - Board: per-layer toggles (copper incl. inner, silkscreen, mask, paste, Edge.Cuts, fab, courtyard, user, drawing
    sheet) with Front/Back/Copper presets, footprints with rect/roundrect/chamfered/circle/oval/trapezoid/custom pads
    and round/oval drills, tracks, arcs, through/blind/micro vias, filled zones, graphics, text, dimensions; back-side
    flip (mirrored view).
  - Footprint and symbol library files standalone (library list with filter, unit and De Morgan selection).
  - Project: a summary of sheets, text variables, net classes and patterns, board rules and presets, schematic
    settings, check severities and pinned libraries, plus the raw JSON.
  - Pan (drag), zoom at the pointer (wheel, pinch, keys), fit, dark/light themes; hover shows pin (with net name),
    symbol, label, pad, track, via, zone and footprint details.
- Fidelity check against `kicad-cli` SVG exports (`tools/kicad/fidelity.mjs`), hand-written KiCad 8 corpus
  (`tools/kicad/make-kicad-samples.mjs`), results in `docs/evidence/kicad/`.

- **CAD Drawing Preview** for 2D drawings: `.dxf` (ASCII and binary, R12–2018+, code pages incl. ANSI_949),
  `.dwf` (DWF 6 packages with W2D sheets, legacy single-stream DWF) and `.dwfx` (XPS FixedPages). Own Canvas 2D
  renderer on a format-neutral scene model (`renderers/cad2d/scene.ts`, reusable by other CAD readers): blocks
  (nested, arrays, attributes), dimensions, hatches (solid, pattern lines, islands), MTEXT formatting, leaders and
  multileaders, wipeouts, linetypes, ACI/true colours, lineweights, OCS; paper-space layouts with viewports; DWF
  polylines/contours/circles/ellipses/text/fonts/colour maps/images/zlib sections, the package thumbnail with a clear
  notice when a sheet uses opcodes it cannot draw; DWFx paths, glyphs, obfuscated embedded fonts, image brushes.
  Viewer: wheel/pinch/button zoom around the pointer, drag pan, fit, layer list with toggles, model/layout/sheet
  selector, dark/light background, line-weight toggle, info bar with version, units, extents, entity counts and
  cursor position. Hangul uses the system fonts (no font bundled). Evidence: `docs/evidence/cad2d/`.
- Samples and tools: `tools/make-cad2d-samples.py` (DXF via ezdxf, DWF/W2D and DWFx written byte by byte),
  `tools/cad2d/` (view screenshots, interaction checks, fidelity against ezdxf's renderer).

## [0.2.4] — 2026-11-24

### Changed
- **Size limits raised to 1 GB** inside the plugin: 3D/CAD files (was 768 MB), Office/HWPX ZIP contents (was 120–400 MB),
  and the most a compressed model may expand to. CAD reading may take up to 30 minutes (was 5), with progress shown.
- **Orca's own 50 MB limit still applies.** "File too large: … exceeds 50MB limit" is Orca's load error: Orca 1.4.263
  (and its current source) reads at most 50 MB before it hands a file to any plugin editor (images and PDFs excepted), and
  offers plugins no other way to read a file (stablyai/orca#46775). A plugin cannot raise it.

### Added
- **`.stpz` (gzip-compressed STEP)**, and gzip-compressed content in any 3D/CAD file: unpacked in the frame
  (DecompressionStream, refused above 1 GB). STEP usually shrinks 5–8×, so large STEP files fit under Orca's 50 MB:
  verified in Orca 1.4.263 — a 58.6 MB `.step` is refused by Orca, the same model as a 10 MB `.stpz` opens (1,332 parts).
- A clear message when a CAD file does not fit in the engine's memory (OpenCascade, 32-bit WebAssembly, 4 GB) instead
  of "damaged". Measured on synthetic STEP assemblies: 61 MB in 1.5 min, 189 MB in 14 min, 343 MB exceeds the time
  limit, 412 MB runs out of memory.
- Harness `--warnings` prints console warnings.

## [0.2.3] — 2026-11-20

### Fixed
- **STEP / IGES / BREP did not open in Orca** (`preview refused: cad-engine`). The OpenCascade engine was started
  from a `blob:` script, which Orca's plugin frames refuse, also inside workers. The vendor build now ships
  `vendor/occt/occt-import-js.csp.js` (the library with its two `new Function` sites replaced, with an LGPL
  modification notice, beside the unmodified file), and the worker loads it by URL. The browser harness now
  refuses `blob:` scripts like Orca. Verified in Orca 1.4.258: a STEP assembly and an IGES part render.
- **Pictures missing in PowerPoint slides**, depending on the picture's format and effects. Checked against
  PowerPoint's own slide export on a 49-case corpus built with PowerPoint (formats, sizes, effects, placements):
  31 → 46 match, 6 → 0 missing.
  - Now shown: TIFF (LZW, multipage), EMF (shapes, text, embedded bitmaps; in-tree player), WMF (rtf.js WMFJS).
  - EXIF-rotated JPEGs are no longer rotated twice (Office stores the rotation on the shape).
  - Recolour (grayscale, black and white, washout, duotone), brightness/contrast, transparency and "set
    transparent colour" are applied; shape picture fills (stretch, tile) and pictures in table cells are drawn.
  - Very large pictures (above 16 MP) are decoded within a size budget.
  - HEIC and JPEG XR show a named placeholder; linked (external) pictures show their path.
- The same picture decoder fixes Word and legacy files: `.docx` 9/14 → 14/14, `.doc` 9/12 → 12/12, `.ppt` 19/23 → 22/23
  pictures shown.

### Added
- `samples/pptx-images/` corpus, `tools/make-pptx-images.ps1` and `tools/pptx-images/` (PowerPoint COM ground truth
  and comparison); report in `docs/evidence/office/pptx-images/report.md`; Orca captures in `docs/evidence/orca-cad/`.

## [0.2.2] — 2026-11-16

### Fixed
- **Install from the Git URL** (`https://github.com/hangams84/orca-file-preview.git` in Orca → Settings → Plugins →
  Install, or `orca plugin install <url>`) failed with "plugin exceeds the install size or file count limit": Orca
  installs the newest `vX.Y.Z` tag and expects `orca-plugin.json` at the repository root, but the tags pointed at the
  whole source tree (tests, evidence, tools). Releases now commit only the plugin to the root of the `dist` branch and
  put the version tag there; the source is tagged `source-vX.Y.Z`. Every release checks the Git URL install in a fresh
  Orca. The installers' online source and the READMEs use the plain repository URL.
- Older tags (v0.1.0–v0.2.1) still point at the source tree, so installing exactly those by Git URL keeps failing;
  their release packages and executables are unaffected.

## [0.2.1] — 2026-11-13

### Fixed
- Windows updater (`update.cmd`, `FilePreviewSetup.exe /update`, `file-preview.ps1 update`) reported a checksum
  mismatch for every download: GitHub serves `.sha256` files as binary, so the hash text was parsed wrongly.
  The v0.2.0 Windows updater cannot update itself — download 0.2.1 once by hand. macOS/Linux were not affected.

### Verified
- Updater against the real v0.2.0 release: Windows 11 (fixed script) and Ubuntu 22.04/24.04 (6/6 each).
